# Top 5 issues and how to resolve them cleanly (2026-09-05)

Requested via `/goal`. Ranked by evidenced frequency/impact across
`docs/judge-report.md` (154 paragraphs scored, 217 complaint lines) plus
2 new tests run today specifically to check whether cheap, zero-new-
grammar fixes exist before recommending anything bigger. Both were
falsified — that result is itself load-bearing (see #5) and changes
what "clean" can mean for #1-2.

## 1. Mechanical/repetitive prose — the dominant failure, and rephrasing doesn't fix it

**Evidence**: 72 of 217 judge complaint lines (33%) say some version of
"mechanical," "repeats," or "reads like a table." This is readiness.md's
Condition 2, shapes 1 and 3.

**Tested and falsified today**: I hypothesized this was a *usage* gap,
not a grammar gap — writers weren't reaching for already-legal
constructs. Two direct tests:
- Same-subject coordination (`"the file is safe and is old"`) already
  parses. But the judge still flagged the *other*, untouched sentences
  in the same paragraph as mechanical — coordinating one pair of
  clauses doesn't fix a whole paragraph's rhythm.
- Different-subject/same-predicate chains (`"the word 'was' is a
  Copula, and the word 'were' is a Copula"`) can already be inverted
  into a colon-list (`"the past Tense uses: the word 'was' or the word
  'were'"`, already used this way in `domain/model.json`). I applied
  this to ADR 0010 and re-judged blind: naturalness went **3/5 → 2/5**,
  not up. The judge called the colon-list itself "templated." Reverted
  the edit — shipping a change that measurably regresses naturalness,
  on a hypothesis I hadn't tested, would have been the same mistake
  flagged in `docs/controversial-decisions-2026-09-05.md`.

**Clean resolution**: the grammar needs a genuinely new sentence-
combining construction — most likely an appositive/parenthetical form
that lets a definition or a second fact ride inside the sentence that
introduces a term, instead of forcing a new flat sentence per fact.
This clears ADR 0048's bar for a new shape (nothing today lets a
definition attach mid-sentence — it is not "a second way to say
something already sayable"). It does not compromise the grammar's
unambiguity in principle (an appositive is delimited by commas the same
way English already does it), but the exact delimiting rule needs a
real LALR(1) conflict check before lock-in, the same way ADR 0050 found
an unexpected conflict with the "obvious" design. **This is the one
item I think needs your go/no-go before I spend an ADR cycle on it** —
see the question below.

**Update, same day**: built as ADR 0054, confined to a singular subject
only (`Subj, NP, Predicate`). Zero LALR(1) conflict on the real build,
zero regression on the full corpus and test suite (`dogfood-sweep`:
1527/1568 before, 1541/1582 after — the +14 is ADR 0054's own file, all
parsing; the pre-existing count is unchanged). But the naturalness
payoff is **not proven**: a direct A/B (fresh blind judges, same
Copula/Function-Word content, flat 2-sentence vs. appositive-collapsed)
scored **4/5 both ways** — tied, not a win. The appositive version's
complaint shifted from "mechanical repeated subject" to "reads like a
glossary entry," which is qualitatively softer but not a higher score
in this single trial. Kept anyway, on the same grounds ADR 0050 was
kept after its own motivating rationale didn't move the score: it is a
genuine capability gain (no construction today lets this happen at
all), zero regression, and a tied n=1 result is one data point, not
disproof — but do not cite it as "the naturalness fix" until it is
tested at scale against several of the 34 real failing documents, the
same bar ADR 0051 (Mapping tables) had to clear (3-for-3) before being
called validated.

**Second update, same day — a skeptic agent audit found 2 real problems
with the above, both now fixed**:
- **The "zero corpus regression" claim was vacuous, not just weak.**
  Nothing in the 1582-sentence corpus — including ADR 0054's own file
  as first written — actually used the appositive construction. A
  before/after diff of the grammar with the production removed was
  byte-identical to with it present. "Zero regression" was true only
  because the feature was completely unexercised, and neither this doc
  nor ADR 0054 said so at the time — exactly the undisclosed-gap
  failure mode `docs/controversial-decisions-2026-09-05.md` exists to
  catch. ADR 0054 now says this explicitly in its own Consequences.
- **The construction only worked in a bare top-level statement, not
  inside `if`/`then`, `so`/`because`, `and`/`or`/`but`-joined clauses,
  or a Step Block** — i.e., not in most of the content this was built
  for. `diagnose` misdiagnosed the failure as an unrelated Enumeration-
  block suggestion, which would have sent a writer down the wrong path.
  Fixed: `ApposSG` added to `Clause` (not just `Statement`) in
  `crates/grammar/src/angloform.lalrpop` — still zero LALR(1) conflict,
  still zero regression (still unexercised by the corpus, per the point
  above), and now verified working inside a real `if/then`, a real
  `because`-clause, a real `and`-coordination, and a bare Step.

A third, smaller gap the same audit found and fixed: ADR 0053's
"packs add, never override" check (`crates/lexgen/src/main.rs`) only
compared a pack's words against core+domain, never against another
already-loaded pack — untestable and untested with only one pack in
place. Fixed and verified live with a synthetic second pack.

## 2. Unclear/unanchored term definitions

**Evidence**: 68 of 217 complaint lines (31%) — abstract terms defined
in one flat sentence, no concrete example, score low on imaginability
even when they parse cleanly.

**Clean resolution**: very likely the *same* grammar addition as #1
fixes both — an appositive construction is exactly what would let an
example ride inline ("a Redirect, the suggestion \"write X instead\",
…") instead of needing its own sentence. Sequence with #1, not after it.

## 3. Coherence relations beyond "cause" are still unbuilt

**Evidence**: `docs/coherence-report.md` / STATUS.md's open decision
queue — only the cause relation (`so`/`because`) has real grammar
support. Exemplification, elaboration, concession, and cross-sentence
sequence do not.

**Clean resolution**: extend one relation at a time, same proven method
as ADR 0037-0049 (grammar-first, LALR(1)-checked, corpus-verified
before and after). Recommend exemplification first — it directly
targets #2's "no concrete example" complaint — but sequence this
together with #1's design pass; they very likely share a root cause
(readiness.md's own diagnosis, now doubly confirmed by today's tests).

## 4. Narrative-register grammar gaps: real, but out of scope

**Evidence**: this session's Frankenstein Letter 1 pilot found no future
tense modal ("will"), "that"-clauses entirely banned, no second-person
object case for "you" (only usable as a subject), no infinitive-
complement clauses ("my task is to assure…").

**Clean resolution — deliberately do not chase this now**: `docs/readiness.md`
defines "usable" as writing a spec, an ADR, or a plan — not narrative
prose. Every one of these gaps only surfaced once I pushed the language
at first-person literary narration, a register the project has never
targeted. Chasing them would be scope creep away from the stated goal.
Recommend recording this explicitly as an intentional boundary (a
future "register" note, not a queued gap) rather than silently
forgetting it or silently starting to close it.

## 5. Two plausible cheap fixes are now empirically ruled out — record this so it isn't re-tried

Not a standalone issue — the finding that makes #1-3 above trustworthy
instead of another round of guessing:
- **Vocabulary is not the bottleneck.** The Frankenstein round-2
  translation, done with a full new 30-word narrative pack in place,
  still scored naturalness 2/5. This is the *second* independent
  confirmation of readiness.md's existing warning ("do not treat this
  as add more words").
- **Rephrasing with already-legal grammar is not the bottleneck
  either**, per #1's ADR 0010 test — the first direct test of that
  specific hypothesis, and it went the wrong way.

Both are now closed questions. The remaining lever is new grammar for
sentence-combining, not more words and not smarter reuse of the words
and shapes that already exist.

## 6. A real methodology test, requested directly by a later `/goal`

The user's own framing: "when something can be harmful but is worth
allowing, confine it structurally to its safe sub-case, with syntax
stricter than a blanket permissive rule." Ran this as an actual
experiment on the appositive's (ADR 0054) inner phrase, not a paper
exercise — 2 rounds, both A/B-tested, the first falsified:

1. **Hypothesis: shorter is safer.** Gibson's DLT says an "of"-chain
   inside the appositive stacks a second open dependency on the
   subject-verb one the appositive already holds open, so restricted
   the inner phrase to ban any "of"-PP. **Falsified**: "The Redirect, a
   term, appears in the Lexicon" (short, no of-chain) scored 2/5 —
   "vague filler... auto-inserted gloss tag" — while "The Redirect, a
   term of the project, ..." (longer, WITH the banned of-chain) scored
   4/5. Length wasn't the cost driver.
2. **Hypothesis: needs any modifier** (adjective or of-PP — ban only
   the completely bare noun). This broke the session's own best
   example, "The Copula, a Function Word, does not take an object" —
   "Function Word" is a bare 2-word domain-term noun with no adjective
   and no of-PP, exactly the shape just banned. Reverted.
3. **What actually worked**: the real distinction is semantic
   (specific noun vs. generic placeholder), which a CFG cannot make —
   "term" and "Function Word" are both just `LNounSg` to the grammar.
   Moved it to Tier 2 instead: `diagnose::vague_appositive` bans a
   small closed list of placeholder nouns (term, thing, kind, sort,
   item, entity, aspect, element, factor, part, piece) from being the
   *entire, unmodified* content of an appositive — the same
   architectural split ADR 0048's same-verb-coordination check already
   uses for a distinction the grammar structurally can't make.
   Verified: bare "term" now flagged, "a term of the project" and "a
   Function Word" both still pass, zero regression.

**Honest limit, not oversold**: a follow-up test on "a strong term"
(adjective added, no of-chain) scored only 3/5 — "strong doesn't
describe a term in any normal sense... reads like a placeholder
qualifier." The word-list check catches the *worst* case (zero
content) cheaply and reliably; it does not, and structurally cannot,
guarantee every appositive is well-chosen — a bad-but-present modifier
still slips through. That is a real, bounded win, not a solved
problem.

**The generalizable lesson for the rest of Condition 2**: "restrict to
the safe structural sub-case" only works when the structural feature
you pick is *actually* correlated with harm — verify that with a real
A/B before trusting theory (cognitive-load reasoning predicted length
would matter; it was wrong here). When the true harmful/beneficial
line is lexical or semantic rather than structural, it belongs in
Tier 2 (a curated check), not Tier 1 (the grammar) — apply this same
test-first discipline to any future "stricter rule" proposal for the
other Condition 2 failure shapes, rather than assuming a plausible-
sounding structural restriction will work.

## 7. Branching direction: the theory was right, the fix still lost

A direct follow-up to §6, prompted by the user pushing on Pinker/Gibson's
actual claim (center-embedding/left-branching is the costly shape, not
length per se — a distinction §6's own test blurred). The appositive
(`Subj, NP, Pred`) genuinely is a mild center-embedding: it suspends
the subject-verb link. Tried to eliminate that by moving the appositive
to a genuinely right-branching position, after the predicate instead of
before it:

- Attempt 1 (bare comma trigger) hit a real, confirmed LALR(1) conflict
  — COMMA was already claimed at the same shared parser state by
  Causal/Conditional/CoordClause.
- Attempt 2 (a dedicated "namely" token instead of punctuation — a
  genuinely unclaimed token, since punctuation was the actual problem,
  not "comma" specifically) built clean, zero conflict, zero
  regression. But it only works comma-less ("the Copula is safe namely
  a Function Word") — a comma before "namely" hits the identical
  conflict, since the ambiguity is on the token immediately after the
  adjective, before "namely" is even visible.
- **A/B result: worse, not better** — 2/5, against the original
  embedded form's 4/5. The missing comma was, per the judge, "the
  smaller problem." The real one: anchoring the trailing appositive to
  an unrelated NP-free adjective predicate forces the sentence to make
  a tangential claim ("is safe") before restating the subject from a
  distance — "two clauses stitched together," not one thought. Reverted
  in full (token, production, seed entry).

**Reconciled, not contradicted**: the branching-direction theory is
correct — center-embedding really does cost more structurally (Gibson's
DLT; the tool's own peak-open metric confirms it directly). It just
isn't the *dominant* cost here. Keeping a restatement adjacent to the
thing it restates is a bigger factor than the embedding's structural
cost, at least at the short lengths this construction is confined to.
This is the same shape of lesson as §6: a plausible, theory-backed
restriction doesn't get to skip the A/B test just because the theory is
real.

## 8. The real scale test: 2 real documents, not synthetic examples

Every result above used one hand-picked content pair (Copula/Function
Word) or synthetic filler ("a term"). The project's own bar for calling
a construction validated (ADR 0051's Mapping tables) is 3-for-3 on real
documents, not a single crafted example — so ran that, on `domain/model.json`'s
own real definitions, picking 2 places where the same-subject "X is a
Y. X does Z." shape the Appositive targets already existed verbatim:

- **`linter`**: "the Linter is a tool of the project. the Linter lints
  a sentence. ..." → "the Linter, a tool of the project, lints a
  sentence. ..." — fresh blind judge, full paragraph, both versions:
  **2/5 → 3/5**. A real, if modest, improvement.
- **`participle`**: "a Participle is a Surface Form of a verb. the
  Participle ends with the suffix "ed" or ends with the suffix "ing".
  ..." → "a Participle, a Surface Form of a verb, ends with ... ..." —
  **2/5 → 2/5**. No change. The judge's complaints moved to the *other*
  sentences in the paragraph (a repeated "ends with the suffix" phrase,
  a circular closing "so a Participle cannot follow a noun") — problems
  the Appositive was never going to touch.

**Honest result: 1 win, 1 tie, 0 losses — not the 3-for-3 bar.** Applied
the `linter` rewrite for real (staged in `domain/model.json`, verified
zero regression). Left `participle` alone — no benefit, and introducing
the construction where it doesn't help is complexity without payoff.

**Reverted, same day, on real human feedback — this is the load-bearing
correction, read it before trusting anything above.** Shown the actual
examples, the user (a real human, not another LLM judge) flagged 2
things no blind subagent judge caught in ~10 trials this session:

1. `Subj, NP, Predicate` is visually identical to an asyndetic list
   (2 comma-separated NPs, no "and") until the verb's agreement
   resolves it — a real garden-path cost for a human reader, independent
   of content, that a formally-unambiguous CFG doesn't rule out. "Proven
   conflict-free" and "doesn't make a human stumble" are different
   claims, and this session conflated them throughout.
2. The user's own comparative judgment: the flat two-sentence original
   ("The Tool is a program. The Tool stores an error.") reads *better*
   than every embedded-appositive example shown, including the
   `linter` rewrite a blind subagent had scored 2/5 → 3/5.

**A single human reaction outranks a single LLM-judge score.** This is
exactly the gap `docs/readiness.md`'s Condition 5 already named before
this ADR existed ("zero data exists on a human... their friction points
are worth more than another synthetic metric") — it just took this long
to actually hit it. Reverted the `linter` change in `domain/model.json`
back to the original two-sentence form. Every naturalness number in §6-8
above should now be read as *LLM-judge-only evidence, contradicted by
the first real human check* — not retracted (the falsified-hypothesis
findings, the LALR-conflict findings, and the "vocabulary isn't the
bottleneck" findings don't depend on this construction being good), but
the Appositive's own naturalness case is now open again, not closed
positive. Do not re-ship it against real corpus content without a human
(not a subagent) confirming it reads better first.
